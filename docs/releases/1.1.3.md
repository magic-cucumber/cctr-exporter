## 可重复构建

脚本：[package-windows.ps1](../../scripts/release/package-windows.ps1)。准备已安装 Gradle、Java 11、用于打包的 JDK 17，以及项目内已有 WiX 和完整运行时镜像；脚本不安装工具，不自动下载或重建运行时。工具路径由参数传入，没有本机 JDK 绝对路径硬编码。

```powershell
# 变量填写本机已有工具路径；读取项目外工具/缓存需获得操作者授权。
./scripts/release/package-windows.ps1 `
  -GradleBat $GradleBat `
  -JavaHome $Jdk11 `
  -PackagingJavaHome $Jdk17 `
  -WixDir build/wix311 `
  -RuntimeImage build/verification-captcha/runtime `
  -ReadOnlyDependencyCache $DependencyCacheRoot
```

`ReadOnlyDependencyCache` 可省略；指定时应指向包含 `modules-2` 的缓存根目录。所有新增文件留在工作区：Gradle 用户缓存写 `.gradle/agent-home`，常规编译中间产物写根项目及各模块的 `build`，最终安装器、打包日志、打包临时目录及工具 home 写 `build/release/1.1.3`。存在同名安装器时脚本拒绝覆盖。

最初已尝试现有 Compose `packageExe`，本地 WiX/runtime 覆盖生效，下载及重建任务均跳过，但 Compose 1.6 的 jpackage 参数文件遇到当前 Windows 中文路径时失败，错误为 `Input length=1`。发行脚本改为直接传递参数调用同一个 JDK `jpackage`，成功生成 EXE；没有修改插件或依赖版本。`windows-local.init.gradle` 留存本地资源覆盖及发布 runtimeClasspath 复制任务。
