# PDF 行内公式基线偏高诊断

## 实物与源码

对 `task_73`、`task_72` 的 6 份 PDF、17 页抽样，量测紧邻两侧同基线汉字的 85 个公式位图。公式图盒底相对正文基线全部为 0.00 pt。图中墨迹最低点在正文基线上方，`task_73` 的 16 处为 3.75–6.00 pt，`task_72` 的 69 处为 3.38–6.00 pt。抽样资源都有软蒙版，未观察到矢量 Form。墨迹边缘说明可见效果，不能代替公式自身基线。

仓库接口示例的 15 个 WIRIS SVG 均有外层 `vertical-align:-Npx`，N 为 4–19，并且 N 等于 `SVG height − wrs:baseline`。现有 `PdfHtmlContent.kt:101、194–237` 按比例缩放后把公式作为行内 `Image` 直接加到段落。代码未把这项对齐信息交给 iText，默认将图盒底放在正文基线上。`DriverUtil.kt:69–73` 为局部截图使用块级资源和四边各 4 CSS px 的防裁留边，返回图片和盒尺寸。未缩窄时，仅底部防裁边便占 3 pt，图内原生空白还会增加可见高度。独立位图检查与这些机制一致。原实物对应的源 HTML 未采集，无法断定每个实物公式的具体偏移量。

## 离线验证

用现有便携包和 iText 8.0.4 解析实际 PDF 绘制矩阵，无需启动浏览器。合成 `vertical-align:-5px` 的公式以 4 CSS px 底部防裁边导出，现行布局的图盒底仍与字基线重合。只设 iText `INLINE_VERTICAL_ALIGNMENT` 在默认模式也不生效。对含公式的段落启用 `HTML_MODE`、在图上设 `FIXED` 后，位图图盒底按预期下降 6.75 pt，无边距矢量下降 3.75 pt，半宽表格中位图下降约 3.37 pt。15 pt 位移样例仍在下一行字形顶端以上保留 1.80 pt。单纯相对坐标下移则与下一行相交 6.42 pt。探针和结果位于 `build/formula-baseline-diagnosis/`。

## 建议修复与验收

1. 优先读取行内公式元素明确的数值 `vertical-align`。若没有该声明而 WIRIS 基线与已知视口尺寸对应，使用它求公式的内部基线。未知来源的内联位图可先只校正测得的防裁底边，保留原图内部空白。普通图片与独立显示公式沿现有规则。
2. 对位图用公式视口底与截图盒底之差计算防裁边，并将它与原公式下沉量一起换算。CSS px 按 0.75 pt 和最终等比缩放换算，2 倍截图像素密度不参与版面位移。矢量使用同一基线计算，截图留边为零。避免通过透明像素裁剪推断下标或分母应处的位置。
3. 优先验证只对需对齐的公式段使用 iText `HTML_MODE` 和 `FIXED`。普通段落沿用原模式。若 HTML 模式影响现有断行、页尾或表格，再用局部渲染器给对齐偏移预留相应行高。验收至少覆盖短符号、上下标、分数、无偏移资源、同一行多公式、窄表格与跨页。检查图盒坐标、下一行间隙、公式四边完整、正文可复制和分页书签。最后用两份真实题库重导对照。

本轮完成诊断和离线验证，产品代码未修改。
