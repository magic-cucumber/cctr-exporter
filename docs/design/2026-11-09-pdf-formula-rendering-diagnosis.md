# 题库 PDF 公式缺失诊断

## 已确认的问题

`task_68` 的抽查覆盖 3 份 PDF、19 页。公式的分母、右侧和局部笔画在页内被切。检查 204 张公式位图，194 张墨迹触及底边，149 张触及右边。受损代表图原位图为 117×47 像素，按 87.75×35.25 pt 完整放入页面，且远离页边。抽查对象未被页面裁剪框截掉，代表图在 PDF 嵌入前已缺内容。统计用于定位这批样本，未遍历全部科目，也没有对应的原始平台 HTML。

## 调用链和独立复现

- `question-list.kt:67、91、98、132` 从平台压缩字段还原题干、答文与选项 HTML。`SelectableQuestionPdf.kt:94、116、125、133` 按题型把这些来源送入同一排版器。选择题的参考答案按既有约定列正确选项标签，公式随选项正文排版。填空题和无选项题可在参考答案区直接排版公式。
- `PdfHtmlContent.kt:100、193` 将 `<img>`、内联 `<svg>` 和 `<math>` 识别为独立资源。SVG 数据 URI 支持百分号或 Base64 编码。仓库接口示例共 15 个 WIRIS SVG，均为百分号编码，SVG 与外层图片有明确像素宽高，且带 `wrs:baseline`、负 `vertical-align` 和 MathML 注释。11 个 SVG 含 `@font-face` 及内嵌字体，交给 Edge，另外 4 个普通 `<text>` SVG 走 iText，离线提取均保留示例 X/i。
- `TaskManager.kt:154` 把局部资源交给 `DriverUtil.kt:58`。Edge 临时页面在 `:66` 使用 `zoom:2` 和 650 px 最大宽度，`:81` 等待图片 `decode()` 和外层 `document.fonts.ready`，`:92` 用 Selenium 元素尺寸与浏览器内窗比较，必要时扩大窗口，`:104` 调用 `WebElement.getScreenshotAs`。已核对便携包内 Selenium 实际发出元素截图命令。代码没有交叉检查实际图像像素、缩放后的元素边界及四边内容。117×47 样本按现有 `.75` 宽度换算与截图像素一致，吻合截图只取未缩放尺寸的假设。需用同款 Edge 记录 `getBoundingClientRect()`、`scrollWidth/Height`、`devicePixelRatio`、截图像素和图片实际宽高，并对照有无 `zoom` 的结果。当前还不能排除源 SVG 自带的 viewport 裁切或嵌入字体问题。外层 `document.fonts.ready` 也无法提供 SVG 图片内部字体已正确成像的独立证据。
- `PdfHtmlContent.kt:201` 把非复杂 SVG 的转换成功及正宽高作为接受条件。用当前便携包离线复现 `<text>Aℝ𝑥B</text>` 生成非空 Form 且没有回退，PDF 中实际只显示和提取 `AB`。同一探针的 `4em`×`2em` SVG 记录单位错误，仍被接受为 4×2 pt 的 Form。仅 `viewBox` 的已测样例则正常计算边界。矢量缺字和尺寸问题独立成立，尚未与 `task_68` 的具体受损位图对应。
- `PdfHtmlContent.kt:140、177、228` 将资源以比例缩放后置入正文行或表格单元格，未读取 `vertical-align` 或 WIRIS 基线。窄列可使长公式缩小，需单独验证可读性。正文中的普通 Unicode 经 `:38` 检查嵌入字体，常见数学符号可输出，缺少 `ℝ`、`ℤ` 和 `𝑥` 时会明确报错。旧版截图 PDF 的 `clean()` 不用于这条题文路径。

探针、原始输出和渲染图位于 `build/formula-pdf-diagnosis/`，使用当前便携包和仓库样本。探针的 Edge 回调为占位实现，只验证分流。本轮未运行实际 Edge 或登录平台。

## 建议修复和验收

1. 在同版本 Edge 上，用带四边标记、分数、上下标的公式复现，并对比当前元素截图、去除 CSS `zoom` 的截图和浏览器视口截图。至少选一条经授权的受损原公式，以浏览器完整画面、提取 PNG 和 PDF 渲染三阶段确认裁切在哪一步发生。
2. 移除 CSS `zoom`。统一测量与截图的坐标系，给公式四周留透明保护边。以未缩放的 DOM 矩形及实际溢出为准调整视口，捕获完整 PNG，可用独立像素倍率提高分辨率。放进 PDF 时单独使用 CSS 逻辑尺寸，别让物理像素决定显示尺寸。比较期望与实收宽高，对明显被截或未加载的资源报告题目 ID。若浏览器完整画面也缺字或缺边，先检查原 SVG 的 `viewBox`、内嵌字体和裁剪规则，保留源布局，避免扩大页面裁剪掩盖源问题。
3. iText 保留已确认可用的路径类 SVG。含 `<text>`、嵌入字体或未验证的 CSS 相对尺寸的公式优先采用经对照验证的局部 Edge 渲染。支持的数学普通文字仍原样输出，确有字体覆盖缺口再按复现范围处理。保留原公式相对位置和基线，宽公式在普通正文、表格和页尾以完整比例验收。
4. 验收覆盖题干、选项和参考答案，含 WIRIS 字体、SVG 数据 URI 两种编码、内联 SVG、MathML、分数根号积分、多行长公式及窄表格。四边标记、首尾符号、上下标与分母在 PNG 和 PDF 都完整，周围文字仍可提取。复查题号、书签、分页、填空答案顺序和错误报告，再由用户用新测试版重导 `task_68` 对照受损页。
